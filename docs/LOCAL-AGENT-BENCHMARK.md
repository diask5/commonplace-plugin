provided a real answer through the application's local task worker. The model was
Conductor's default **gpt-6.1-sol, high effort**. No deployment or real account sync
was performed.

## Full application round trip

The parent submitted a natural-language request using the browser's New task form.
The normal CloudWorker claimed it, pinned an archive snapshot, and waited for the
separate agent. The agent searched that snapshot using production ArchiveTools and
returned its own answer with six citation IDs. The worker validated the result,
persisted it, and the browser displayed the exact answer under Completed.

The answer correctly stated the launch date/time, rollback owner, gate and probes,
and calculated USD 1,550 remaining infrastructure budget. It distinguished approved
decisions from earlier proposals and an untrusted vendor assertion. This answer was
not generated by the demo's canned response function.

## Browser findings and fixes

- Desktop search, project filtering and source reads worked. The 390-pixel mobile
  viewport had no horizontal overflow.
- Deleted conversations disappeared from search but left empty rows in the saved
  library. Fixed in source: library visibility now uses the same current-message
  selection as the archive. A regression covers deletion, stale replicas and newer
  restored content. On the exact test database, the corrected list contains 100
  readable conversations and excludes the deleted vendor note.
- Worker reconnecting appeared in the original evaluation app because the test
  harness stopped ticking after collection. The reusable harness now keeps ticking,
  and the real-agent adapter preserves the heartbeat during long model turns.
  In that stale baseline session, a setup dialog also blocked task-composer
  interactions; the separate active-worker app completed the task successfully.
  This observation does not establish a production dialog-navigation defect.
- **Open UI gap:** answer citations are raw IDs with no clickable source navigation.
- Source reads appear inline below the results rather than in a modal; the evaluator
  initially expected a Close button. Scrolling and inspecting the page resolved it.
- Relevance ranking can place an earlier proposal above a later approved decision.
  The agent read both and resolved the conflict; ranking alone does not establish
  which source is authoritative.

After the source changes, **36 focused tests passed**: 9 local environment/browser
checks, 16 unified-context/grader regressions, and 11 context/library/coverage checks.

## Scope and limits

This was one guided diagnostic run with a synthetic corpus and two fixture collectors,
not a repeated statistical comparison or an evaluation of Kyle's private chat archive.
The evaluator was told not to read source or answer keys; it was not OS-isolated from
them. Source collection, indexing, retrieval, citations, task leases, persistence and
browser rendering used real code. Google login, installation identities and native
host delivery remained fixtures. The real model ran in Conductor through an explicit
local adapter, not the production subscription/container runner. Real OAuth, account
limits, container isolation and Meet Proxy native wake require live acceptance tests.
No token-cost comparison was collected. The original development preview remains
running; no production settings changed.

The benchmark harness and library fix are committed as `6076a49`. On 22 October,
the backend bundle was rebuilt from that commit and passed the full 305-test
application suite, 49 UI checks, 10 deployment checks and package integrity. The
plugin ZIPs for that backend-only fix were byte-identical. The subsequent atomic
capture update produces new runtime-48 archives. See the rollout record for current
artifact hashes and deployment status; this benchmark did not modify production.

## Reproduce and inspect

From `.context/commonplace-source`, run `npm run benchmark:local` for the blind
retrieval harness, or `npm run benchmark:worker` for a full real-agent worker handoff.
Use a new output directory and free ports for each run. See
[local development instructions](LOCAL-DEVELOPMENT.md).
