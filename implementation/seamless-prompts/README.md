# Seamless-flow held-out benchmark

Runs against 0.4.25/runtime58 using new synthetic project facts and fresh chats.
The original 0.4.24 benchmark and approved retest remain immutable in
`../natural-prompts` and their evidence records. The exact runtime hash is pinned
in release.json after packaging. Run on the existing owner-authorized Mac hosts;
only the already approved per-process tools may be allowed. Saved permissions,
account identity and production sharing policies are not changed by this harness.

The private-financial-notes case that the provider rejected in the earlier run is
not retried or rephrased to bypass that decision. It remains an unpassed model
case; deterministic gate regressions are reported separately.

Actual native retrieval uses the real collected private archive with new fictional
notes. Space actions use disposable state, real signed OAuth/MCP and deterministic
classifier fixtures, intended to avoid production spaces or external invitations. The first 0.4.25 run exposed unrelated host apps and actually created an empty ChatGPT Drive Space; that failure is preserved and cleanup is pending. Model cases
remain normal human prompts without tool names or retrieval coaching. Golden data
is outside each empty case directory, not OS isolated; tool receipts are inspected.

## Controlled follow-up

`isolation.py` now disables apps, computer/browser features, command tools, web
search and other MCP servers for each Codex process. It verifies effective flags
and server selection without starting a model, then stops on unexpected tools or
denials. It does not change saved permissions. Acceptance and the private-finance
case previously denied are not retried. The controlled run is narrower than a
normal host and cannot replace the failed default-host routing result. Claude
seed/scored processes disable builtin command tools; exact approved MCP read tools
retain their process-only allowance. No new blanket approval is added.

`start-when-ready.py` now checks the current held-out projects from plan.json and
requires both seeded notes plus active runtime58. It observes only by default;
`--start-score` explicitly starts model cases after those receipts. A published
ZIP, a running older daemon or copying a setup prompt cannot satisfy readiness.

The Claude process allowance contains exactly search_shared_context,
read_shared_context and context_folder_status, all explicitly approved by the
owner earlier for benchmark processes. It adds no saved allow rule. The stream
guard is secondary detection after an event is emitted; it cannot undo a tool
that already started. Effective disabled features and server selection provide
the isolation boundary for the controlled Codex runs.
